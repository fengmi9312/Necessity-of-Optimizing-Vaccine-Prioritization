# Necessity of Optimizing Vaccine Prioritization

Code for the manuscript **“When is vaccine prioritization worth optimizing?”**

This repository contains simulation, analysis, and figure-generation code for studying when optimized vaccine prioritization is epidemiologically warranted under limited vaccine supply. The framework quantifies the **epidemiological necessity of optimization** as the attainable final-burden range generated by feasible age-specific vaccine allocations that all use the same total vaccine supply.

The code implements an age-structured non-Markovian SIRVP model, computes objective-specific optimal and burden-maximizing allocations, evaluates cumulative infections and deaths, and analyzes cross-objective trade-offs between infection control and mortality reduction.

## Conceptual summary

For a prevention objective \(q\), epidemiological necessity is defined as

\[
N_q = \tilde{\chi}_q(\vartheta_q^{\max}) - \tilde{\chi}_q(\vartheta_q^{\mathrm{opt}}),
\]

where \(\vartheta_q^{\mathrm{opt}}\) is the feasible allocation that minimizes the final burden \(\tilde{\chi}_q\), and \(\vartheta_q^{\max}\) is the feasible allocation that maximizes the same burden under the same fixed vaccine supply. A large \(N_q\) indicates that allocation choices can substantially change epidemic outcomes. A small \(N_q\) indicates that many feasible allocations perform similarly, so the additional epidemiological gain from selecting the optimized allocation is limited.

The main analyses consider two prevention objectives:

- cumulative infections, denoted by \(q=c\);
- deaths, denoted by \(q=d\), using age-specific infection fatality rates as objective weights.

The repository also evaluates cross-objective penalties,

\[
\Phi_x^{(y)} =
\frac{\tilde{\chi}_x(\vartheta_y^{\mathrm{opt}}) - \tilde{\chi}_x(\vartheta_x^{\mathrm{opt}})}
{\tilde{\chi}_x(0) - \tilde{\chi}_x(\vartheta_x^{\mathrm{opt}})}, \qquad x \neq y,
\]

which measure how much of the vaccination benefit for objective \(x\) is sacrificed when using the allocation optimized for objective \(y\). These penalties identify cross-objective trade-off intervals in which infection-minimizing and death-minimizing allocations have materially different epidemiological consequences.

## Installation

Use a recent Python 3 environment. The code has been organized for Linux/HPC execution and can also be adapted for local runs.

```bash
git clone https://github.com/fengmi9312/Necessity-of-Optimizing-Vaccine-Prioritization.git
cd Necessity-of-Optimizing-Vaccine-Prioritization

python -m venv .venv
source .venv/bin/activate

pip install numpy scipy pandas matplotlib scikit-learn filelock openpyxl
```

## Workflow

The repository follows a three-stage workflow:

1. Run simulation experiments.
2. Convert raw simulation outputs into analysis tables.
3. Generate manuscript and supplementary figures.

### 1. Run simulation experiments

Simulation experiments are registered in `ExperimentalCode/task_info.py`. The command-line entry point is `ExperimentalCode/main.py`:

```bash
python ExperimentalCode/main.py <task_idx> <task_amount> <expr_name> <task_param>
```

Arguments:

- `task_idx`: index of the current worker or batch job;
- `task_amount`: total number of workers or batch jobs;
- `expr_name`: experiment name, matching an entry in `ExperimentalCode/task_info.py`;
- `task_param`: task-specific parameter label.

Example single-worker run:

```bash
python ExperimentalCode/main.py 0 1 necs_from_example baseline
```

Example distributed run over 40 workers:

```bash
for i in $(seq 0 39); do
    python ExperimentalCode/main.py "$i" 40 necs_from_param baseline
done
```

Available experiment modules include parameter scans, contact-profile analyses, fatality-risk heterogeneity analyses, country-specific estimates, optimization-transition analyses, time-course simulations, and cross-objective trade-off analyses. See `ExperimentalCode/experiments/` and `ExperimentalCode/task_info.py` for the complete task list.

The execution wrapper writes each completed task to Excel files in the relevant output folder. Temporary files are written first and then renamed after successful completion.

### 2. Build analysis tables

After the simulation outputs are available, run:

```bash
python AnalysisCode/analysis_main.py
```

`AnalysisCode/analysis_main.py` loads raw experimental outputs, applies task-specific analysis functions, and writes processed Excel files to `AnalysisData/`.

Before running a full reproduction, inspect the final active values of `task_dict` and `anal_list` in `AnalysisCode/analysis_main.py`. The script is designed for selective processing, so the active list should be set to the analyses required for the target figure set.

### 3. Generate figures

After `AnalysisData/` has been created, run:

```bash
python FigureCode/figure_main.py
```

`FigureCode/figure_main.py` loads processed analysis tables with `AnalysisCode.analysis.get_anal_data`, dispatches figure-specific drawing functions from `FigureCode/figure_func/`, and saves PDF outputs under `Figure/<figure_name>/`.

Before generating a target figure set, inspect the final active `selected_fig_dict` block in `FigureCode/figure_main.py`. The script supports both main-text and supplementary figure groups.

## Core model components

The model code is located in `Dependencies/CodeDependencies/`.

Key files:

- `model.py`: age-structured non-Markovian SIRVP model and allocation optimization routines;
- `model_time_course.py`: time-course simulation routines;
- `basic_params.py`: baseline parameters;
- `param_data_loader.py`: demographic, contact, fatality, and country input loaders;
- `func.py`: numerical helpers, growth-rate and reproduction-number calculations, and Excel export utilities.

The core simulation represents age-specific susceptible, infected, removed, vaccinated, and protected states. Vaccinated individuals enter protection after a vaccine-response delay with vaccine efficacy, while infection and removal follow non-Markovian event-time distributions. The model maps an age-specific allocation to final cumulative infections and objective-weighted final burden.

## Experiment modules

`ExperimentalCode/experiments/` contains task-specific simulation modules. Important groups include:

- `necs_from_param.py`: necessity landscapes over transmission intensity and vaccine-response delay;
- `necs_from_fatality.py`: death-minimizing necessity under varying IFR heterogeneity;
- `necs_from_contact.py`: robustness to contact-profile changes;
- `necs_from_country.py` and `param_from_country.py`: country-specific parameterization and estimates;
- `optm_transition.py`: optimal-allocation transitions;
- `tradeoff_between_effects.py`: cross-objective trade-off analyses;
- `necs_from_time_course.py`: time-course examples;
- `necs_from_growth*.py`: growth-rate based transmission-intensity analyses;
- `direct_effects_*.py`: direct/indirect protection orientation analyses.

Each module exposes an `execute(task_param, file_idx)` function that is called by `ExperimentalCode/tasks.py`.

## Reproducibility notes

The repository is designed for batch computation. Many scans require multiple jobs and can take substantial time depending on the grid size, optimization settings, and number of initializations.

For a reproducible public release, include:

```text
requirements.txt
LICENSE
CITATION.cff
README.md
Zenodo/OSF/Figshare data archive DOI
scripts/reproduce_main_figures.sh
scripts/reproduce_supplementary_figures.sh
```

A recommended minimal archival workflow is:

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Download or unpack archived data
# Place external inputs under Dependencies/DataDependencies/

# 3. Rebuild analysis tables from existing simulation outputs
python AnalysisCode/analysis_main.py

# 4. Generate figures
python FigureCode/figure_main.py
```

A full-from-scratch workflow should additionally run the required `ExperimentalCode/main.py` tasks listed in `ExperimentalCode/task_info.py` before the analysis step.
